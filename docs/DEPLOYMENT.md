# 배포 가이드

이 문서는 Game Designer Portfolio의 배포 및 운영 절차를 정의한다.

---

## 1. 목적

배포 및 운영 절차를 정의한다.

배포 실수를 줄이고, 누구나 동일한 절차로 배포할 수 있도록 하는 것이 목표다.

---

## 2. 배포 환경

| 환경 | 역할 |
|------|------|
| GitHub | 소스 코드 저장 및 버전 관리, PR 기반 협업 |
| GitHub Actions (향후) | 빌드/린트/테스트 자동 검증 (CI) |
| Vercel | `main` 브랜치 기준 자동 빌드 및 배포 (프로덕션 호스팅) |
| Custom Domain (향후) | 실제 서비스 도메인 연결 |

---

## 3. 배포 절차

```
feature/docs 브랜치 작업
   ↓
Commit
   ↓
Push
   ↓
Pull Request
   ↓
Merge to main
   ↓
Vercel 자동 배포
   ↓
배포 확인
```

`main`에 병합되는 즉시 Vercel이 자동으로 빌드 및 배포를 수행한다.

---

## 4. 배포 전 체크리스트

- [ ] 빌드 성공
- [ ] ESLint 오류 없음
- [ ] TypeScript 오류 없음
- [ ] 링크 확인 (내부/외부 링크 정상 작동)
- [ ] PDF 확인 (다운로드 및 내용 정상)
- [ ] 이미지 확인 (누락/깨짐 없음)
- [ ] 반응형 확인 (모바일/태블릿/데스크톱)

---

## 5. 배포 후 체크리스트

- [ ] 메인 페이지 확인
- [ ] 프로젝트 페이지 확인
- [ ] PDF 다운로드 확인
- [ ] 모바일 확인
- [ ] 성능 확인 (Core Web Vitals)

---

## 6. 버전 관리

버전은 다음 형태로 관리한다.

- `v0.1` : 초기 구조 및 기본 페이지 구축
- `v0.2` : 콘텐츠 및 기능 추가
- `v1.0` : 정식 배포 (모든 섹션 완성, 실사용 가능 상태)

버전은 `main`에 병합되는 주요 마일스톤 시점에 태그로 기록한다.

---

## 7. 장애 대응

배포 실패 또는 배포 후 문제가 발견되면 다음 순서로 대응한다.

1. **원인 확인** — 빌드 로그, 에러 메시지, 변경 범위를 확인한다.
2. **이전 커밋 확인** — 직전 정상 배포 커밋을 확인한다.
3. **Rollback** — Vercel에서 이전 정상 배포로 즉시 되돌린다.
4. **수정 후 재배포** — 원인을 수정한 새 브랜치를 만들어 PR로 다시 반영한다.

`main`에서 직접 수정하지 않는다.

---

## 8. Claude Code 협업

Claude Code는 다음을 절대 자동으로 수행하지 않는다:

- 자동 배포
- 자동 Merge
- 자동 Push

Claude Code는 배포 준비까지만 수행한다. (코드 수정, 체크리스트 확인, 변경 사항 설명 등) 실제 배포 실행 여부는 항상 사용자가 결정한다.

---

## 9. 배포 직전 최종 체크리스트

- [ ] 배포 전 체크리스트를 모두 통과했는가
- [ ] PR이 리뷰 및 승인되었는가
- [ ] 관련 `docs/` 문서가 최신 상태인가
- [ ] 병합 대상 브랜치가 `main`인지 확인했는가
- [ ] 배포 후 확인할 항목(5장)을 인지하고 있는가
- [ ] 문제 발생 시 Rollback 절차(7장)를 알고 있는가
