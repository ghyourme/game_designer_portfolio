# Content Editor (로컬 전용)

`data/*.json`을 웹 폼으로 편집하는 로컬 전용 도구다. 배포되지 않는다 — Next.js 앱과
완전히 분리되어 있고, `next build`/Vercel에 포함되지 않는다 (`docs/ARCHITECTURE.md` §10 참고).

## 실행

```
npm run content-editor
```

`http://127.0.0.1:4321`을 브라우저로 열면 된다. `127.0.0.1`에만 바인딩되므로 같은
네트워크의 다른 기기에서는 접근할 수 없다 — 본인 컴퓨터에서 실행한 사람만 쓸 수 있어
별도 로그인을 두지 않는다.

## 사용법

1. 왼쪽에서 편집할 데이터 파일을 고른다.
2. 필드를 수정한다. 배열형 콘텐츠(Projects, Analysis, Personal Works 등)는 항목별로
   "삭제" 버튼과, 맨 아래 "새 항목 추가" 버튼으로 늘리고 줄인다.
3. "저장"을 누르면 해당 `data/*.json` 파일에 그대로 반영된다.

## 사진 업로드

Projects의 썸네일/커버, 갤러리 이미지처럼 이미지 경로 필드는 파일 선택 버튼이 함께
있다. 사진을 고르면 실제 Next.js 앱의 `public/images/` 아래(프로젝트별 폴더)에
저장되고, 필드 값에는 그 결과 경로(`/images/...`)만 채워진다 — 사이트가 이미 그
경로를 그대로 서빙하므로, 저장 후 다시 배포하면 바로 보인다. PNG/JPEG/WebP/GIF/SVG만
허용되며, 업로드 즉시 도구 안에서 미리보기가 뜬다.

## 안전장치

- 저장할 때마다 저장 직전 상태를 `data/.backups/`에 타임스탬프와 함께 남긴다
  (`.gitignore` 처리되어 커밋되지 않는다). 잘못 저장했다면 이 폴더에서 이전 파일을
  복사해 되돌리면 된다.
- 저장 전 서버가 최소한의 형태 검증(배열이어야 할 파일에 객체를 넣는 등)을 한다.
- 그 외의 실제 콘텐츠 품질(근거, 문체 등)은 `docs/CONTENT_GUIDE.md`의 체크리스트를
  기준으로 직접 검토한다 — 이 도구는 검증을 대신하지 않는다.

## 필드 구조를 바꾸려면

`schema.js`가 `docs/DATA_MODEL.md`의 필드 정의를 폼으로 옮긴 것이다. `data/*.json`의
필드가 바뀌면(Architecture Decision을 거쳐 `docs/DATA_MODEL.md`와 `types/*.ts`를 먼저
갱신한 뒤) `schema.js`도 함께 갱신한다 — 세 곳이 어긋나면 이 도구가 실제 데이터 구조와
다른 폼을 보여주게 된다.
